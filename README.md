# HK STORE

واجهة إدارة محل HK STORE بالعربية، مع تطبيق Windows وتطبيق Android.

## الوظائف الحالية
- المبيعات ومخزون البيع والزبائن والديون والتقارير والنسخ الاحتياطي محلياً على كل جهاز.
- حسابات مدير وبائع وتقني وزبون اللوح، مع إظهار الواجهات حسب الدور.
- تسجيل أجهزة الصيانة ومتابعة الحالات.
- مخزون مستقل لقطع غيار الصيانة.
- خدمة طلب تعبئة الرصيد بين جهاز Windows ولوح Android على شبكة Wi-Fi المحلية: يحدد البائع المتعامل والمبلغ، ويُدخل الزبون رقم الهاتف، ثم يراجع البائع الطلب ويؤكده.

## إعداد ربط لوح الزبون
1. ثبّت وشغّل تطبيق HK STORE على جهاز Windows واجعله متصلاً بشبكة Wi-Fi نفسها التي يتصل بها اللوح.
2. سجّل الدخول إلى Windows بحساب المدير أو البائع. سيبدأ خادم الشبكة المحلي على المنفذ 8787، وستظهر نافذة فيها عنوان جهاز البائع ورمز ربط اللوح.
3. على اللوح، افتح تطبيق HK STORE. في شاشة الدخول أدخل عنوان جهاز البائع ورمز اللوح ثم اضغط «حفظ الاتصال».
4. أنشئ حساب «زبون اللوح» على اللوح من حساب المدير (يمكن استخدام حساب المدير الأولي عند الإعداد فقط)، ثم ادخل بحساب الزبون. على جهاز البائع، حدد المتعامل والمبلغ؛ سيظهران على اللوح. يدخل الزبون رقم هاتفه ويرسله، ويظهر الطلب عند البائع خلال ثوانٍ.
5. اسمح لتطبيق HK STORE عبر جدار حماية Windows على الشبكة الخاصة عند ظهور الطلب. لا تفتح المنفذ 8787 على الإنترنت.

## بيانات الدخول الأولية
حساب المدير الأولي: اسم المستخدم `manager` والرمز `1234`. غيّر الرمز فور الإعداد وأنشئ حسابات العاملين. لا تترك الرمز الافتراضي.

## حدود مهمة قبل الاستخدام التجاري
- خدمة التعبئة الحالية تسجل الطلب وتؤكد استلامه داخلياً فقط؛ لا تنفذ شحناً فعلياً. يلزم عقد/حساب موزع معتمد أو API رسمي لكل متعامل لإجراء التعبئة.
- مزامنة Wi-Fi الحالية تخص طلبات التعبئة فقط. بيانات المبيعات والمخزون والزبائن والصيانة لا تزال محفوظة محلياً على كل جهاز وليست قاعدة بيانات مشتركة.
- كلمات مرور حسابات التطبيق الحالية محفوظة محلياً بصيغة غير مشفرة؛ لا تستخدم بيانات حساسة أو تشغيل مالي حقيقي قبل استكمال نظام مصادقة وتخزين آمنين واختبارات الأمان.
- رمز اللوح ورمز البائع مخصصان للشبكة المحلية. لا تشارك رمز البائع، ولا تستخدم شبكة Wi-Fi عامة.
- مواقيت الصلاة والتنبيهات لم تُربط بعد بمصدر مواقيت معتمد.


## تكامل HK AI وHK Software Bridge

### إعداد الذكاء الاصطناعي الحقيقي (على جهاز Windows فقط)
الخادم الوسيط موجود في تطبيق Windows، ومفتاح المزود لا يُرسل إلى المتصفح ولا يُحفظ في بيانات التطبيق أو مستودع GitHub. لتفعيله:
1. احصل على مفتاح API من مزود متوافق مع واجهة OpenAI Chat Completions. لا ترسله في المحادثات ولا تضعه في ملفات المشروع.
2. افتح PowerShell على جهاز Windows الذي سيشغّل HK STORE ونفّذ الأوامر التالية مع وضع مفتاحك مكان النص المؤقت:
   ```powershell
   setx HK_AI_API_KEY "ضع_مفتاحك_هنا"
   setx HK_AI_MODEL "gpt-4o-mini"
   setx HK_AI_BASE_URL "https://api.openai.com/v1"
   ```
3. أغلق HK STORE وافتحه من جديد حتى يقرأ متغيرات البيئة. يجب أن يكون الجهاز متصلاً بالإنترنت.
4. افتح حساب المدير أو التقني لتشخيص الأعطال، أو حساب البائع ثم صفحة المنتجات لمساعد الإكسسوارات.

قد يفرض مزود الذكاء الاصطناعي رسوماً حسب الاستعمال. لا يتم تفعيل الذكاء السحابي قبل إضافة مفتاح صحيح. لا تُدخل بيانات شخصية حساسة للزبائن في وصف العطل.

### ربط أجهزة Android عبر USB
- ثبّت Android SDK Platform-Tools على جهاز Windows وأضف مجلد `platform-tools` إلى متغير PATH.
- فعّل USB debugging على هاتف الاختبار، وصِل كابل بيانات، ثم وافق على بصمة RSA من الهاتف.
- من مختبر السوفتوير اضغط «كشف أجهزة USB». الجسر يقرأ قائمة ADB واسم الشركة والموديل فقط.
- لا ينفذ الجسر أوامر مسح أو تفليش أو فتح أقفال. التفليش يحتاج أداة الشركة الرسمية وملف Firmware مطابقاً تماماً ورمز الموديل والمنطقة وموافقة الزبون. لا توجد أداة واحدة آمنة لكل الشركات.
- لا تستخدمه لتجاوز FRP أو Activation Lock أو تغيير IMEI. استرداد الحساب وفتح الشبكة يكونان عبر القنوات الرسمية وإثبات الملكية.

### حدود التكامل
- مساعد HK AI يقدم اقتراحات فنية ومبيعات، وليس تشخيصاً نهائياً؛ افحص القياسات والقطعة فعلياً قبل الاستبدال.

- مختبر السوفتوير يتيح اختيار جهاز تم كشفه عبر ADB وتعبئة الموديل وإصدار Android وBootloader ورمز المبيعات إن أتاحه الجهاز؛ قد لا تتوفر المنطقة/CSC ويجب إدخالها والتحقق منها يدوياً. هذه البيانات لا تثبت توافق Firmware. كما يتضمن قائمة تحقق أولية قبل التفليش: رقم الطراز والمنطقة وBootloader وإصدار Android ورقم البناء ومصدر HTTPS وبصمة SHA-256 وموافقة الزبون والنسخ الاحتياطي. تحفظ سجلات القائمة محلياً على الجهاز. اكتمالها لا يثبت سلامة الملف أو توافقه؛ يجب مطابقة البصمة والتوقيع مع مرجع الشركة الرسمي. لا تنفذ هذه الشاشة التفليش.
عند تسجيل خدمة سوفتوير يمكن اختيار الجهاز المكتشف وإرفاق لقطة من بيانات ADB المقروءة (الشركة، الموديل، Android، Bootloader، Codename، Product وبصمة النظام) بسجل العملية للرجوع إليها لاحقاً. لا تُخزن هوية USB التسلسلية تلقائياً في هذه اللقطة.
- جسر USB الحالي للقراءة والكشف فقط: يقرأ الشركة والموديل وCodename وProduct وإصدار Android وبصمة النظام عبر أوامر ADB للقراءة فقط. لا ينفذ أوامر تعديل أو مسح أو تفليش.
- بيانات التعريف تساعد التقني على مطابقة الجهاز قبل البحث عن Firmware؛ لا تكفي وحدها لإثبات توافق ملف النظام. يجب مطابقة رقم الطراز والمنطقة/CSC وإصدار Bootloader ومصدر الملف الرسمي وموافقة الزبون.
- لا يوجد حتى الآن تنفيذ تفليش فعلي أو موصل أدوات شركات. سيضاف كل موصل رسمي بشكل مستقل بعد توثيق الأداة والإصدار ومسارات التحقق واختبارها على أجهزة تجريبية.

### مواصفات الشواحن والكابلات والاقتراح المباشر في البيع
- عند إضافة شاحن أو كابل، يسجل المدير نوع المنفذ (USB-C أو Lightning أو Micro-USB)، والقدرة بالواط، وبروتوكول الشحن إن كان معروفاً، وطول الكابل اختيارياً، إلى جانب موديلات الهواتف المتوافقة.
- لا يظهر الشاحن أو الكابل ضمن الاقتراحات المؤهلة إذا كانت بيانات المنفذ أو القدرة ناقصة؛ ولا يستنتج التطبيق القدرة أو البروتوكول من اسم المنتج وحده.
- يعرض المساعد المنتجات المطابقة والمتوفرة مع الصورة والسعر والكمية، ويفصل المنتجات النافدة أو التي تنقصها المواصفات.
- زر «إضافة إلى البيع» يختار المنتج ويملأ السعر والكمية في نموذج البيع. لا يسجل عملية البيع ولا يخصم المخزون إلا بعد ضغط البائع على «تأكيد البيع».
- تعمل المطابقة المحلية حتى إذا لم يتم إعداد مفتاح HK AI. الذكاء الاصطناعي مساعد اختياري ولا يملك صلاحية اختراع توافق أو إضافة منتج غير موجود في المخزون.

### سلة البيع متعددة المنتجات
- يمكن إضافة عدة منتجات إلى سلة واحدة، مثل الهاتف وواقي الشاشة وواقي الصدمات والشاحن والكابل.
- يحتفظ كل سطر بسعره وكمّيته، ويُجمع المنتج نفسه في سطر واحد عند تطابق سعر الوحدة.
- يتحقق التطبيق من المخزون المتاح لكل منتج عند الإضافة، ثم يعيد التحقق من جميع الكميات قبل تأكيد العملية.
- عند التأكيد تُخصم الكميات مرة واحدة، ويُسجل إجمالي واحد ومدفوع واحد ودين واحد للزبون؛ ولا يُخصم أي مخزون بمجرد إضافة منتج إلى السلة.
- يصدر وصل واحد للعملية ويعرض تفاصيل جميع المنتجات والكميات والأسعار والإجمالي والمدفوع والمتبقي.
- السلة مؤقتة داخل جلسة البيع الحالية؛ إفراغ السلة أو إعادة تحميل التطبيق قبل التأكيد يلغي محتوياتها دون تغيير المخزون.

### استكمال حماية سلة البيع
- تُحفظ السلة محلياً لكل حساب بائع/مدير على حدة، وتُستعاد بعد إعادة تحميل التطبيق أو تسجيل الدخول مجدداً على الجهاز نفسه.
- تظهر قيمة الإجمالي والمدفوع والمتبقي مباشرة أثناء إعداد الفاتورة.
- لا يسمح بتسجيل دين دون اختيار زبون مسجل، حتى لا تضيع المبالغ المتبقية على زبون عابر.
- يعيد التطبيق تجميع كميات المنتج نفسه والتحقق من مجموعها مقابل المخزون عند تأكيد البيع، وليس كل سطر منفرداً فقط.
- لا يقبل إضافة منتج بسعر وحدة فارغ، ولا يسمح لحساب التقني أو الزبون بالتلاعب بسلة البيع.
- تبقى السلة محلية على الجهاز؛ مزامنتها بين جهاز البائع واللوح ليست جزءاً من هذا الحفظ المحلي.

## بناء ملفات التثبيت
يُنشئ GitHub Actions ملف APK تجريبياً للأندرويد وملف EXE محمولاً لويندوز عند كل تحديث على الفرع main. ملفات البناء التجريبية ليست توقيعاً رسمياً للنشر على متجر التطبيقات.


### التحقق من الملكية وموافقة حذف البيانات
- سجل خدمة السوفتوير يطلب طريقة إثبات الملكية وتأكيد التقني للتحقق منها، وموافقة الزبون الصريحة على الإجراء.
- يمكن توثيق عدم حذف البيانات أو النسخ الاحتياطي أو إعادة ضبط المصنع/مسح البيانات أثناء تثبيت Firmware.
- إجراءات المسح تتطلب تأكيد النسخ الاحتياطي أو إقرار الزبون بتعذر النسخ وقبوله فقدان البيانات.
- إعادة ضبط المصنع لا تزيل FRP أو Activation Lock؛ قد يطلب الجهاز الحساب السابق بعد المسح. استرداد الحساب يكون عبر الشركة أو القنوات الرسمية فقط.
- هذه إضافة للتوثيق والموافقة والسجل؛ لا تنفذ أوامر مسح أو تفليش تلقائياً ولا تتجاوز أقفال الحماية.

### دليل أدوات التفليش
يتضمن مختبر السوفتوير دليلاً إرشادياً لمسارات Android Platform Tools (ADB/Fastboot)، وHeimdall مفتوح المصدر لبعض أجهزة Samsung، وأدوات الشركات، وRecovery/OTA، ومسارات MediaTek وQualcomm. الدليل يشرح احتياطات التوافق ومخاطر الملفات الحساسة ولا ينفذ أوامر تفليش أو مسح من داخل التطبيق. الأدوات الخارجية يجب تنزيلها من مصادرها الموثوقة وفحصها والتحقق من مطابقة ملفات Firmware للجهاز. لا يدعم تجاوز FRP أو Activation Lock أو تغيير IMEI.

### مطابقة واقيات الشاشة وواقيات الصدمات والإكسسوارات
- في المخزون، اختر فئة المنتج وأدخل موديلات الهواتف المتوافقة مفصولة بفواصل. سجّل كل موديل بعد التأكد من المقاس والفتحات، خصوصاً الكاميرات والأزرار في أغطية الحماية.
- يستخدم مساعد الإكسسوارات مطابقة موحدة لحروف الموديل والمسافات والشرطات، لكنه لا يخمّن توافق موديلين مختلفين.
- عند نفاد منتج، يعرض المنتجات الأخرى المتوفرة فقط إذا كانت مسجلة صراحة على أنها متوافقة مع موديل الهاتف نفسه. إذا لم يوجد بديل موثق، يبلغ البائع بعدم توفر بديل ولا يقترح منتجاً عشوائياً.

### صور المنتجات وربطها بعدة موديلات
- يستطيع المدير عند إضافة منتج إدخال رابط صورة HTTPS، واختيار الفئة (مثل واقي شاشة أو واقي صدمات)، وإدخال عدة موديلات متوافقة مفصولة بفواصل.
- تعرض قائمة المخزون صورة المنتج وفئته والموديلات المرتبطة به والكمية وأسعار الشراء والبيع.
- لا يعتمد مساعد الاقتراحات إلا على الموديلات التي سجلها المدير صراحة بعد التحقق الفعلي من توافق المنتج.

### طلبات الزبائن وقائمة مشتريات الجملة
- يستطيع البائع أو المدير تسجيل سلعة غير متوفرة مع فئتها وموديلها ومواصفاتها والكمية المطلوبة واسم الزبون ورقم هاتفه.
- يمكن تسجيل السعر المتوقع وملاحظات خاصة بالطلب.
- تُجمع الطلبات المفتوحة تلقائياً في قائمة احتياجات واحدة قبل التسوق من سوق الجملة، مع إمكانية طباعتها.
- يمكن متابعة كل طلب عبر الحالات: بانتظار الشراء، تم شراؤه، وصل إلى المحل، تم تسليمه للزبون، أو ملغى.
- لا تُحتسب هذه الطلبات كمبيعات ولا تخصم من المخزون؛ تبقى طلبات توفير مستقلة حتى إتمام البيع فعلياً.
- تحفظ الطلبات ضمن قاعدة بيانات التطبيق المحلية وتدخل في النسخ الاحتياطي.
